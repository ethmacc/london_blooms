# London Blooms — Technical Specification

A 4bit retro-style React web application that predicts cherry blossom blooms in London and displays notable viewing locations on an interactive map.

Implements `prd.md > The Core Journey`, `prd.md > Features and Behavior`, and `prd.md > Look and Feel`.

## Where It Runs and How Someone Tries It

**Run locally:**
```bash
npm install
npm run dev
```

**Open:** http://localhost:5173 (or the port shown in the terminal)

**To demo:** Open the browser, show the homepage with map and onboarding message, hover over pins to display location info, click navbar to view history page, and show the hit counter.

## How This Works, In Plain Language

1. **You open the app** → It loads a homepage with a map on the right and an onboarding message on the left, with falling cherry blossoms in the background.

2. **You hover over map pins** → Each pin shows the location name, a cherry blossom image, how many trees are there, and when they bloom.

3. **You click the navbar** → It switches to the history page with information about cherry blossoms in London.

4. **A lucky cat shows your visitor count** → It's saved in your browser and keeps increasing as you refresh.

5. **If something breaks** → A classic game-style lucky cat appears saying "gomenasorry" instead of crashing.

## Data Sources

### locations.json
Converted from `resources/london_cherry_blossom_locations.csv`. Contains 12 London locations with:
- Location name
- Estimated number of trees
- Google Maps link
- Access level (free/paid)

### prediction.json
Generated by running `a.js`. Contains:
- Predicted bloom date for next season
- Temperature conditions at bloom
- Confidence level

**Task during build:** Run `a.js` to generate this file from `resources/historical_weather.json`.

### history-content.json
Curated, paraphrased facts from the official Royal Parks article at https://www.royalparks.org.uk/read-watch-listen/ten-things-you-might-not-know-about-cherry-trees. It is stored locally so the page does not need a runtime request. Contains:
- Origins of cherry blossoms in London
- Diplomatic exchanges
- Special characteristics of local species

**Task during build:** Curate and paraphrase facts from the Royal Parks source, and link to it from the History page.

## Components

### App
- Root component that manages navigation between pages
- Sets up the cozy classic game theme
- Handles error state display

### Map (page component)
- Displays MapLibre map centered on London
- Renders pins at 12 cherry blossom locations
- Shows onboarding message beside map
- Triggers hit counter increment on page load

### Pin
- Renders on map at location coordinates
- Shows location name, image, tree count, and bloom date on hover
- Hides info when hover ends
- Uses placeholder image (simple colored circle with cherry icon)

### FallingBlossoms
- Renders multiple cherry blossom particles falling from top to bottom
- Randomized positions and speeds
- Classic game pixelated style

### CursorBlossom
- Renders a cherry blossom that follows mouse cursor
- Classic game pixelated style
- Optional: hide on non-interaction

### HitCounter
- Displays visitor count with lucky cat image
- Reads from localStorage on mount
- Increments count and saves to localStorage
- Classic game aesthetic styling

### Navbar
- Simple link to navigate to History page
- Classic game aesthetic styling
- No routing library (simple state-based navigation)

### History (page component)
- Displays historical information about London cherry blossoms
- Static content from history-content.json
- Classic game aesthetic styling

### ErrorState
- Displays when map or prediction data fails to load
- Shows classic game-style lucky cat image with "gomenasorry" text
- Provides button to return to home

## States and Error Handling

### Normal use
- Map loads successfully
- Pins hover and show info
- Navigation works between pages
- Hit counter increments

### Error state
- Map fails to load → Show lucky cat "gomenasorry"
- Prediction data fails to load → Show lucky cat "gomenasorry"
- Fallback: Display static London map background if MapLibre fails

### First use
- User opens site → Sees onboarding message beside map with falling cherry blossoms animation

### Hover state
- Hover over pin → Info appears (name, image, tree count, date)
- Stop hovering → Info disappears

## Decisions and Open Issues

### Hit counter storage
- **Decision:** Browser localStorage
- **Reason:** Simple for PoC, no backend needed
- **Tradeoff:** Only tracks visits on single browser, not global count

### Image sources
- **Decision:** Placeholder images for pins and animations
- **Reason:** Simple to implement, easy to replace later
- **Tradeoff:** Less visually appealing than real photos

### Prediction data source
- **Task:** Run `a.js` to generate prediction.json
- **Reason:** Uses historical weather data algorithm
- **Tradeoff:** Static prediction, not real-time

### History content source
- **Decision:** Curated, paraphrased facts from the Royal Parks website, stored in a local JSON file
- **Reason:** Official, accredited source
- **Tradeoff:** The static facts need manual updates if the source or project content changes

### Map provider
- **Decision:** MapLibre GL JS (free, no API key)
- **Reason:** No cost, no rate limits, good for PoC
- **Tradeoff:** Less polished than commercial providers

### Navigation approach
- **Decision:** State-based (not React Router)
- **Reason:** Simpler for PoC, no extra dependency
- **Tradeoff:** More code as app grows
