A small guide to the code

London Blooms

A local web app that pairs a cherry-blossom forecast with London viewing spots, a hoverable map, and a short history of the trees.

A short reference route

Use this route to find where a pin’s details come from. It is a reference, not a claim that we toured these files together.

  1. 1. The data — src/data/locations.jsonEach place supplies the coordinates and details that the map can show.
  2. 2. The interaction — src/components/Map/index.jsx, MapComponentSearch for mousemove and setFeatureState. The hovered GeoJSON feature is matched back to a location record.
  3. 3. The result — popup.setLngLat(...).setDOMContent(...).addTo(map)The popup follows the pointer and displays the matched location name, tree count, and bloom date.

To change this, start here

  • Forecast date or confidenceUpdate public/data/prediction.json; src/App.jsx loads it and passes it into the Home page.
  • Map places or their detailsEdit src/data/locations.json. The map reads these records for both pin positions and popups.
  • History storiesEdit src/data/history-content.json. src/pages/History/index.jsx renders the cards and links to their Royal Parks source.
  • Blossom motionStart at src/components/FallingBlossoms/index.jsx for particle timing and src/components/FallingBlossoms/falling-blossoms.css for the keyframes.

A practice to reuse

The falling blossoms initially appeared but did not animate: the React component supplied unitless values to CSS timing properties. Checking the browser’s computed style exposed animation: none; adding units changed it to fall, and the production build passed. For another UI issue, trace the value from its source through the style rule to the browser’s computed result, then verify the visible behavior.
